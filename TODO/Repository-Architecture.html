01Overview

Gemini CLI is a terminal-first AI coding agent. The same engine (packages/core) powers four different front-ends: the interactive terminal UI, an Agent2Agent HTTP server, a programmatic SDK, and an Agent Client Protocol mode for IDE hosts. A single bundled artifact — bundle/gemini.js — is both the npm bin target and the subject of the integration test suite.

The next-speaker decision — the loop terminator

packages/core/src/utils/nextSpeakerChecker.ts:43-137. Getting this wrong is the classic agent-loop bug, so the implementation is conservative in two ways:

  1. It uses curated history, not comprehensive history :53. Comprehensive history contains invalid/empty parts that would 400 on resubmit :49-52.
  2. Two short-circuits avoid an LLM call entirely :73-95: if the last comprehensive message is a function response → model; if the last curated model message has empty parts → model.

Only when the last curated turn is a real model message does it issue one generateJson call with modelConfigKey: { model: 'next-speaker-checker' }, role LlmRole.UTILITY_NEXT_SPEAKER, against a 3-rule ordered rubric :14-18. Errors are swallowed with a debug warning and return null :130-136.

Turn bound MAX_TURNS = 100 at packages/core/src/core/client.ts:79. This is the hard backstop that prevents a tool-confirmation loop from running forever even when loop detection does not fire.

Strong architectural decisions

1. The bundle is the tested artifact

Integration tests run bundle/gemini.js, not src. Release verification installs from the real registry and runs the suite against the installed binary. Failures are therefore caught in the shape users actually get.

2. Environment isolation enforced by lint

Banning os.homedir()/os.tmpdir() outside core's helpers is what makes the harness's HOME sandboxing reliable. A convention would have decayed; a lint rule cannot.

3. Snapshot-based scheduling

The UI receives a full ToolCall[] after every transition rather than per-event lifecycle messages. Combined with the discriminated-union status model, the UI cannot observe an impossible state, and parallel batches render with no sequencing logic.

4. Layered defenses at the shell boundary

Git hooks, pagers, credential helpers, SSH commands, interactive prompts, and PTY encodings are all neutralized in shellExecutionService.ts:553-639 — so every shell tool call is guarded regardless of which tool issued it.

5. Graceful edit degradation

Exact → whitespace-flexible → token-regex → fuzzy (10%-weighted threshold), each telemetry-tagged, followed by an LLM repair pass gated on a stale-content hash. Designed so a model's whitespace imprecision is not a hard failure.

6. Policy-derived exclusions hide tools

getExcludeTools() unions policy exclusions, which then remove tools from the model-visible declaration set. The model never sees what policy forbids — it cannot ask for it.

7. Core builds first, always

Both scripts/build.js:40-49+ and the release publish order exist because CLI and a2a-server cannot typecheck or run without a freshly published core.

8. Hook-modified inputs are disclosed

When a hook rewrites tool_input, the modification is reported back to the model coreToolHookTriggers.ts:164-179. The model is never silently lied to about its own arguments.

9. Deferred error semantics

scheduler.ts:478-487 deliberately parks pre-flight errors rather than failing them immediately — one malformed tool call must not stall a parallel batch.

10. Tests without a network mock

Rather than an HTTP-level Gemini mock, determinism comes from record/replay of the content generator through the real bundle. Elegant, and it also means genuine transport-level API behavior is only exercised in nightly evals.
